# 夜席 · 第二版设计：现场感、音效、电子牌

第一版把桌子做成一本安静的账本，这在远看数字时是清楚的，但坐在桌边会觉得空：没有筹码落地，没有牌的厚度，也没有声音。第二版要把「正在打牌」加回来，同时保住夜席的气质——夜里一张漆过的桌子，不要赌场霓虹，不要金币雨，也不要去复制小丑牌（Balatro）的原画、小丑或牌背。

本文件是第二版的界面与感官规格。规则以 `docs/PRODUCT_SPEC.md` 为准，尤其是双模式、底牌保密和电子牌自动判定。第一版的颜色、字体、字号、按钮含义和设备分工仍然有效，见 [visual.md](visual.md)、[flows.md](flows.md)、[components.md](components.md)。本文件只写需要升级或新增的部分。

## 气质

夜席还是夜席：墨绿毡面、暖白数字、黄铜只做标记。第二版加深的是材料和光线，不是另换一套皮肤。

- 毡面要能看出一层短绒：细颗粒、中央一束暖光、四周略收暗。椭圆外沿是一圈薄黄铜轨，不要木纹贴图铺满屏幕。
- 筹码是陶土色的陶瓷片，有厚度和齿边，不是金币，也没有货币符号。
- 牌要有厚度、阴影和一层很克制的箔光。电子牌的牌面是本仓库自己的印刷设计，偏奢侈的字体牌，而不是卡通角色牌。
- 动效是桌上的物体在移动，不是 UI 元件在弹跳。禁止花色粒子、红闪、老虎机滚动、按钮弹跳。
- `prefers-reduced-motion: reduce` 时：物体不飞、牌不旋转，只用 80–120ms 的淡入交代结果；音效保留，因为那是现场感的另一半，但提供独立的静音开关。

## 两种模式在桌子上怎么看

创建房间时，用两张大选择卡选打牌方式，文案直说：

- 实体牌：我们自己发牌，系统只记筹码。
- 电子牌：系统洗牌发牌，底牌只在自己手机上，摊牌按牌力分池。

不要把这个选项藏进高级设置。电子牌作为预选项，因为这是完整的新体验；点一下即可改回实体牌。两手之间，主持可以再改。进行中的一手不能切换。

**实体牌**：桌子中央仍是底池和边池，但下注和分池要看到筹码在飞。中央可以保留街名（翻前、翻牌圈…），不要出现虚拟牌面。

**电子牌**：桌子正中出现五个公共牌位，像浅浅的牌槽。翻牌、转牌、河牌依次填入并翻开。每个在局座位前有两张缩小的牌背；摊牌时未弃牌者翻开，并在座位下写牌型。底池数字改到牌槽上方，边池仍在下方。手机行动页上，自己的两张底牌是最大的物件，微微呈八字打开。

## 牌

比例接近标准扑克 2.5 : 3.5。电脑上公共牌大约 86×120，座位前的底牌大约 36×50；手机上自己的底牌大约 132×184，横过来时可以略缩小但必须两张并排完整可见。

用 CSS 3D（`transform-style: preserve-3d`），不要为了牌再引入 Three.js 或构建步骤。一张牌是有正反面的物体：

- 厚度用 3–4px 的漆面倒边表示。
- 静止阴影 `0 18px 32px rgba(0,0,0,0.45)`。翻开和飞入时阴影跟着抬升、落下。
- 箔光是一层低透明度的旋转锥形渐变叠在牌面和牌背上，混合模式用 soft-light 或 overlay，透明度不超过 0.28。待机时 8–12 秒缓缓扫过；指针在牌上时，箔光跟随指针，牌体最多倾斜 10 度。减少动效时去掉倾斜和扫光。

### 牌背

底色 `#0e1512`。双线黄铜框，四角有小括号饰。中央一个椭圆章，里面一个「夜」字，字用暖白或浅黄铜，不要英文 logo，不要复制自行车牌或任何商业牌背。框内可以有很淡的几何扭索纹（SVG 线纹），密度要低，远看是一块深漆，近看才有纹。

### 牌面

纸色 `#f4efe4`，加一层极淡的纤维噪点，不要发灰，不要纯白。黑色花色墨水 `#1a1714`，红色花色 `#b23a2f`。角标用本仓库已有的数字字体，A / K / Q / J / 10 / 9… 清晰、偏大。花色符号用本仓库自己画的 SVG（黑桃、红心、方块、梅花），轮廓略偏雕刻，不要用系统 emoji，也不要下载现成牌面素材。

点数牌按传统点阵摆放。人头牌（J/Q/K）不要画人物肖像，以免撞到通行的牌面版权。用巨大的字母作主图形，配黄铜线饰和一块小箔面即可，皇家同花顺和人头牌的箔面可以略强，普通点数牌只留很薄的纸光。

发牌、翻开、摊牌的节奏：

1. 电子牌开手：先短促洗牌声，再从庄标记处依次飞出底牌。每张间隔约 60ms，飞行 420–520ms，带轻微 rotateZ。先发一圈，再发第二圈。公共牌槽此时是空的。
2. 翻牌：烧牌不露面。三张牌叠着滑入槽位，再依次翻开，间隔 80ms。
3. 转牌、河牌：一张滑入并翻开，380ms。翻面在旋转过半时换成正面。
4. 摊牌：未弃牌者的座位底牌翻开，360ms，随后牌型名称淡入。不要同时翻全桌再让人找，按庄家左侧依次翻，间隔 120ms。

实体牌模式不做上述发牌动画。

## 筹码与分池动画

数字仍然是权威，筹码堆是数字的身体。把任意正整数拆成常规面额：1000、500、100、25、5、1。对应陶土色，大致为琥珀、紫、黑、绿、蓝、白，都是哑光陶瓷，中间有一圈凹槽和短齿边，不用金属高光闪片。

- 座位右侧或牌前有一座余筹码，高度随数量增加，最多画出有限的可见片数，余下用压缩表示，避免十人桌卡死。
- 下注、跟注、加注、下盲：从该座位飞出一组筹码，沿短弧进入底池，落地时有错落（20–40ms），同时数字从座位减到池里加。飞行约 400ms。加注和全下的堆更厚、声音更沉。
- 全下：剩余全部入池，座位余码归零，标签「全下」在落地后出现。
- 未被跟注退回：一小撮从池返回该座位。
- 分池确认后：按池依次分配。主池先走，再边池。每个池的筹码分成一到多道弧线飞向赢家座位，落地后座位数字跳到新值。平分时两道（或多道）同时出发。余数那 1 个筹码单独、很短地飞向应得的人，不要悄悄加在数字里。整段分池仪式控制在大约 1.2–2 秒（池多为上限），结束后才允许开下一手；减少动效时跳过飞行，直接改数字。
- 撤销：不播一遍倒放电影，只用短促的收回声，数字和牌面立刻回到撤销后的状态。

中央底池附近要看得到池中的筹码堆，而不是只有一个数字。边池用更小的堆，贴在各自的边池牌旁边。

## 音效

音效是这一版的关键，用户要求的是「真实牌桌」而不是游戏提示音。定位是安静的私人牌局：近距离、偏干、木头桌面、陶瓷筹码、纸牌。客厅里不要老虎机、不要人群嘈杂、不要赢钱号角。

### 音色表

| 事件 | 声音 | 备注 |
| --- | --- | --- |
| 过牌 | 指节在桌沿轻敲一下 | 短、木、无金属 |
| 下注 / 跟注 | 2–5 枚筹码先后落在毡上 | 每枚音高和间距略作随机 |
| 加注 | 一摞筹码放下，随后一两枚单独落下 | 比跟注重、低 |
| 全下 | 更密的筹码倾倒，最后一声实的闷响 | 不要警报 |
| 弃牌 | 纸牌轻滑，再轻轻一贴 | |
| 洗牌 | 一次短的 riffle | 只在电子牌开手 |
| 发底牌 | 每张一次清脆的抽牌/弹牌 | 音高微变，避免机枪感 |
| 翻开公共牌 | 发牌 + 翻面（纸边拍案） | 翻牌三张可重叠，但不要糊成一团 |
| 庄标记移动 | 很轻的陶瓷片滑动 | |
| 分池入账 | 筹码推向赢家，再落地 | 平分时两组交错 |
| 余数那 1 个 | 单枚轻落 | |
| 操作失败 | 极轻的干点击 | 不是蜂鸣 |

### 实现与控制

- 全部音效必须是本仓库原创：用脚本生成 WAV（例如 `tools/make-sounds.mjs`）再在页面里播放，或用 Web Audio 精细合成后缓存。禁止从网上下载商业音效包，禁止抽取其他游戏的音频。
- `public/audio/table-sound.js` 统一管理。浏览器要在第一次指针或按键后解锁 `AudioContext`。若被挡住，牌桌角落出现一句「轻触开启牌桌音效」，点一下即消失并开声。
- 电脑总览和手机都有静音按钮（喇叭图标），状态写入 `localStorage` 键 `night-table.sound`，默认开。静音时图标要能一眼看出来。主音量要克制，发牌和筹码是前景，UI 失败音明显更弱。
- 同一事件连续触发时，播放速率在 0.96–1.05 之间抖动，并错开 10–30ms，避免完全相同的重叠。
- 没有「背景音乐」。

## 界面改动要点

- 启动页创建表单增加打牌方式的二选一，其它默认值不变。
- 牌桌顶栏增加静音；电子牌时街名旁边可以看到已发出的公共牌缩略，避免只看得到数字。
- 手机行动页：上方是自己的两张底牌（实体牌模式则不出现牌，仍以剩余筹码为最大数字），中部是底池与「轮到谁」，底部仍是行动按钮。电子牌摊牌后，这里也展示自己的牌型和公共牌。
- 电子牌分池工作台预填系统判定，主持主要是核对和确认。不要再让主持点选赢家；若要表达「系统已按牌力判定」，用一句短说明和牌型对照，而不是把选择器开放改判。
- 实体牌分池工作台保持第一版的点选交互。
- 远看原则不变：先看见谁在行动，再看见底池。牌和筹码不得挡住中央「轮到谁」和底池总额。

## 技术边界

- 继续：无构建步骤、本机 Node 服务、WebSocket 按凭证下发快照、SQLite 持久化、局域网 Host 限制。
- 快照必须按人裁剪。公共状态可以有 `dealMode`、`board`（已公开的公共牌）、每位玩家是否已持有底牌、摊牌后的亮牌和牌型。`hole` 只出现在该玩家自己的视图。测试要覆盖：A 的 WebSocket 消息里没有 B 的底牌；主持视图在摊牌前也没有任何人的底牌；日志在摊牌前不泄漏点数。
- 旧房间数据缺字段时，按实体牌恢复，不能因为升级而丢房间。
- 动画和音效是表现层，游戏对错以服务端状态为准。动画播放期间到达的新状态要能衔接或跳到最终态，不能卡死操作。
