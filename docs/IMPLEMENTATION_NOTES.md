# 实现说明

## 技术与目录

- Node.js 内置 HTTP 服务；`ws` 提供 WebSocket 状态广播，HTTP JSON 请求提交操作。
- Node.js 内置 `node:sqlite`，WAL + `synchronous=FULL`。每个房间一行完整状态，每次写入包括游戏状态、日志、撤销快照和请求去重记录，使用 SQLite 原子提交。
- 原生 JavaScript ES modules 与 HTML/CSS，无构建步骤。`public/styles.css` 从设计稿样式复制为生产基础，`public/app.css` 补充真实输入、无障碍及响应式规则。`docs/design/` 原文件未修改。
- `qrcode` 编码真实局域网加入 URL；纠错 M、4 模块安静区、深色模块与暖白底。不使用设计中的示意 `qr.svg`。
- 运行时字体为自托管的 SIL OFL 子集：Noto Serif SC、Noto Sans SC、Inter、Fraunces，位于 `public/fonts/`，不依赖 CDN 或 npm 字体包。许可证文件与 `public/fonts/README.md` 一并提供。

## 权限、并发与恢复

玩家和主持是两个独立的 256 位随机持有者凭证，分别保存于浏览器 `localStorage`。数据库只存 SHA-256 哈希。请求只使用自己的凭证，不接受客户端自报的角色；玩家操作使用由凭证解析出的玩家 ID，客户端传别人的 ID 无效。公开快照不包含凭证、哈希或撤销历史。二维码中没有主持凭证。

创建房间要求同时满足 TCP 来源为回环地址、Host 为 localhost/回环地址。已有主持凭证可以继续使用，局域网普通设备不能借创建或恢复入口获得权限。一次性移交在服务端替换主持哈希，消费后无法重用，旧 WebSocket 会立即收到看客视图。

服务端统一处理状态转换，所有命令带版本号；过期命令返回 409 并刷新状态。请求带独立 ID，最近 512 条成功命令去重；同一玩家加入重试复用相同凭证和座位。每条变更先在复制状态上完成校验和守恒断言，再原子落盘，最后广播。HTTP 的失败不会留下半次扣款。

WebSocket 订阅第一帧携带凭证，不把凭证放入 URL。心跳每 15 秒检测连接，仅用于在线标记，绝不触发游戏动作。浏览器自动重新订阅并获取完整快照；多标签页任一连接在线仍算在线。服务器重启后，原凭证、当前轮次、行动人、投入和日志都从 SQLite 恢复。

最近 200 次操作支持逐步撤销。开手和自动收盲是一笔，分池和所有获奖入账是一笔；下注与伴随的未匹配退回也是一笔。分池预览不算可撤销的下注操作。撤销恢复之前的完整状态，但版本号继续递增，旧请求不会因回退而再次有效。全部手牌日志保留，展开页可选择历史手数。

## 规则实现要点

下注状态机：`betting → roundEnd → betting`，只有主持的 `next` 会推进翻牌/转牌/河牌；最后一轮、仅剩一人未弃牌，或没有可继续争夺的下注时转到 `showdown`。主持确认后才转 `settled`。没有任何计时器推进街或代弃牌。

行动队列 `pending` 显式记录这一轮还该行动的人：每次有人投入后，所有本轮投入低于 `currentBet` 的可行动者都进入队列（短码全下也一样，已跟注的人要补跟或弃牌）。`actedAt` 记录每人上次行动时面对的 `currentBet`；只有 `currentBet - actedAt ≥ lastFullRaise`（或本轮还没行动过）时才有加注权，所以多次短码累计达到完整幅度会对相应的人重开加注权（Poker TDA 第 49 条）。最小加注以 `currentBet + lastFullRaise` 计算，短码不改变 `lastFullRaise`。4.0 及以前的实现让已跟满者不必补跟，4.1.0 已修正；旧快照在恢复时按当前街的动作重建 `actedAt` 与欠跟注的 `pending`。

一轮完成时，唯一最高本轮投入超过第二高的部分退还原玩家，并记录日志。底池金额按总投入层级计算，资格是该层投入者中仍未弃牌的玩家；相邻同资格层合并。4.0 及以前的短码不补差规则可能在旧数据里留下“较高总投入者在之后一轮弃牌”的情况，只有弃牌者贡献的高层死钱并入最近有有效资格的下层，不创建无合法赢家的池。这一边界由固定随机种子的合法序列测试覆盖。

结算再次由服务端重算，不能信任客户端预览。每池先整数平分，余数按照庄家左侧到右侧的顺时针座位顺序，只发给已选有资格赢家。客户端显示相同算法的预览，服务端核对完整选择、资格、去重、预览池总额和守恒。

所有操作均断言：`全场 = 所有座位剩余 + 所有池`。补码、加入与离开显式变更全场总额并写日志；无其他改筹码接口。所有数量采用安全整数并限制单次输入上限。主机的操作区没有代下注按钮，手机没有主持按钮。

## 界面验证

遵循设计里的深色漆面、暖白数字、少量黄铜、琥珀行动色。电脑使用椭圆座位环，屏幕顺时针与逻辑座位顺序一致；两人分列左右，庄和小盲同卡。十人卡片缩小，窄屏总览切换为中央状态、座位列表和日志。进行中加入者在下一手条展示，避免改变当前座位几何。

手机以 375×667 为基准、320 宽无横向溢出。操作区使用 56px 按钮与 sticky 底部；跟注/过牌单击，弃牌/全下/分池/撤销二次确认。对话框用原生 `dialog` 管理焦点与遮罩，默认焦点落在安全按钮；回合版本变化自动关闭未提交面板。支持 `prefers-reduced-motion` 和实时状态读屏。

分池工作台按设计分成池列表、资格赢家、预览三栏，窄屏堆叠。合法完整预览同步到玩家手机；不完整选择清除共享预览。全部池都有赢家且分配守恒才启用确认。预填唯一有资格的赢家仍需主持确认。

# 第二版实现说明

版本 2.0.0。第一版的筹码规则、权限、持久化和局域网限制都保留。本版补上现场感，并增加电子牌模式。

## 双模式

房间配置增加 `dealMode: 'physical' | 'digital'`。`newRoom` 在未指定时默认为实体牌，以保持旧测试与旧存档兼容；创建页把电子牌作为预选项。缺少该字段的旧房间在 `normalizeRoom`（读取与 `apply` 时）按实体牌恢复，不会丢档。两手之间主持可用 `setDealMode` 切换，进行中的一手拒绝切换。

实体牌的推进与点赢家逻辑与第一版相同：一轮结束停在 `roundEnd`，主持点「下一轮」；摊牌后按池点选赢家。电子牌在 `start` 时用 `node:crypto` 的 Fisher–Yates 洗 52 张牌，从庄家左侧（两人局是大盲）发两圈底牌；主持点「下一轮」时先烧牌再发翻牌 3 张或转牌/河牌 1 张。若已无人可再下注且仍有多于一人未弃牌，则自动发完剩余公共牌并进入摊牌。只剩一人未弃牌则不必亮牌，池归该人。

摊牌后 `autoWinners` 按标准德州 7 选 5 为每个池判定赢家（平分与余数规则不变），写入 `hand.selections` 与 `hand.preview`。确认分池时若选择与系统判定不一致，服务端拒绝。牌力模块在 `server/cards.js`，判定是确定性的。测试可用 `setNextDeck` 注入牌序；正式开手走 `takeDeck()` → `shuffle()`。

## 底牌保密

完整牌局（含 `deck`、`burned`、`holes`）只留在服务端状态与撤销快照里。`store.view` 经 `clipView` 按身份裁剪后再交给 HTTP 与 WebSocket：公共状态可有 `board`、是否已发底牌、摊牌后的亮牌和牌型；`hole` 只出现在该玩家自己的视图顶层。主持与看客在摊牌前看不到任何人的底牌。摊牌前日志只写「已发底牌」。前端座位上的牌背也不会把他人点数写进 DOM。

## 音效与动画

`tools/make-sounds.mjs` 生成本仓库原创的短 WAV，由 `public/audio/table-sound.js` 统一播放。第一次指针或按键后解锁 `AudioContext`；若被挡住，角落出现「轻触开启牌桌音效」。静音键写入 `localStorage` 键 `night-table.sound`，默认开。`prefers-reduced-motion: reduce` 时不飞筹码、不旋转翻牌，只用短淡入；音效保留但可静音。动画是表现层，数字以服务端状态为准。新状态到达会取消未完成的飞行（`fxGen`），避免卡死按钮。撤销根据日志变短识别，不倒放，立刻回到撤销后的状态。分池入账期间暂时禁用「新的一手」，飞行动画结束后再打开。

牌面是自制 SVG：牌背中央「夜」字，人头牌用字母和线饰，不画人物肖像。实现用 CSS 3D，没有 Three.js 或打包器。

## 第四版：一整晚的流程

已知限制与产品边界见 [README](../README.md) 和 [CONTRIBUTING.md](../CONTRIBUTING.md)。

### 数据

- `state.status`：`open` / `ended`。`mutate` 入口统一检查，已结束的房间只读（`牌局已经结束，只能查看。`）。`end` 只能在两手之间，写 `endedAt`。撤销照常可用，所以「撤销散场」就是撤销上一步。
- `state.roster`：按玩家 id 的账本，`buyIn`（起始 + 补码）、`rebuys`、`cashOut`、`seated`、`leftAt`。入座、补码、离开、移出都在引擎里同步更新。离开的人用同一台手机回来，沿用原 id，`buyIn` 累加。今晚已用过的名字不能被别人拿去入座。
- `state.records`：每手在分池时生成结构化记录：动作序列（含每步后底池）、起始筹码、公共牌、自愿或摊牌亮出的底牌及牌型、弃牌、分池、每人投入与所得、VPIP。散场总结和牌谱都只读它，不解析文字日志。
- 前注是死钱：计入 `contribution`，不算 `bet`；不够前注就全下前注，边池按投入层自然正确。盲注级别按 `LEVELS` 倍数表，`levelEvery` 手自动升级，也可 `level ±1`。
- 撤销快照压缩：不再存 `logs`/`records` 的副本，只存长度和最后一条记录；二者只追加，撤销时截回。广播视图只带当前手和最近 60 条日志，`logCount`/`recordCount`/`lastRecord` 供前端判断；完整日志、牌谱、总结走 `GET /api/rooms/:code/log|hands|summary`。

### 总结（`server/summary.js`）

- 每人：总带入、补码次数、最终筹码或带走、净值 = (最终 + 带走) − 带入、打了几手、拿下底池次数、最大一笔所得、单手最大净收、入池率（翻前主动投入；大盲过牌、被迫的盲注和前注不算）、全下手数、摊牌次数、亮过的最好牌（只看他自己公开过的牌）。
- 账平：总带入 = 最终筹码 + 提前带走 + 池中。另外逐人核对「每手净值之和 = 账本净值」（`consistent`），测试里对 40 个随机长夜逐一断言。账本校验不做成阻断断言，避免账本代码的缺陷让一晚局卡死；规则层守恒仍是阻断的。
- 高光最多 4 条：最大底池、最强亮牌（两对以上）、单手最大收获、全下之王（≥2 次）、最爱入池（手数足够的人里最高，至少两人合格）。不够条件就不显示，不编数字。
- 旧房间：`normalizeRoom` 从日志里的「坐到 N 号位 · 起始」「补码 · X +N」「X离开，带走 N」还原账本；匹配不上的标 `approx`。统计从 `statsFrom`（升级后的下一手）开始，界面写明。

### 身份与请求

- 角色新增 `departed`：离开的人凭原凭证仍能看到自己的总结，也能再入座。
- 认领座位：`POST claim`（新手机凭证 + 选中的玩家）→ 主持 `decide-claim`。同意后把该玩家的凭证哈希换成新手机的，旧凭证立即失效；15 分钟过期。新手机提交后换一条 WebSocket 连接，按新身份收视图。
- 申请补码：`POST ask` → 主持 `decide-ask`，内部就是一次 `rebuy` 命令，照常进撤销历史。
- 接回主持：`POST reclaim-host` 只接受 loopback 地址加 localhost Host；`rematch` 同样只在本机，按原设置开新桌并在旧桌写 `nextRoom`。
- 代操作：`timeout` 命令只在行动计时已到或行动者离线（服务端在线表判断）时可用，能过就过，不能过才弃。

### 前端

- `public/night/recap.js`：大屏排行、手机个人总结、文字战报、分享图（Canvas 1080 宽，花色用路径绘制，导出 dataURL——CSP 不放开 `blob:`）。
- `public/night/replay.js`：牌谱列表与时间线。`public/night/device.js`：屏幕常亮（Wake Lock；局域网 http 不是安全上下文时退回到静音循环小视频，服务端为此支持 Range 请求）、震动、标题提示、记住上次房间。
- 复制：安全上下文用 Clipboard API，否则退回 `execCommand('copy')`，再不行弹出可全选的文本框。
- 计时环与计时条每 250ms 只更新 CSS 变量和数字，不重绘整页；最后 5 秒变朱砂色，不闪烁。
- PWA：`manifest.webmanifest` + 图标（`node tools/make-icons.mjs`）。不注册 Service Worker（局域网 http 不允许）。
- 新增界面文字后要重新生成字体子集：`python3 tools/subset-fonts.py <google/fonts 源 TTF 目录>`。
- 实机截图：`node tools/shoot-v4.mjs <输出目录>` 打完一整晚并截图。
